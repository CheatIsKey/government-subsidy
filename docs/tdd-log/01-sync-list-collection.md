## 목표

행정안전부 공공서비스(혜택) 정보 API에서 혜택 목록 전체를 받아 검사·정리해서 PostgreSQL에 저장하고, 실행마다 기록을 남긴다.

## 케이스와 결정 (중요한 것만)

| 결정 | 이유 |
|---|---|
| 한 번에 1,000건씩, 설정 상한 2,000 | 실측: 3,000 이상은 HTTP 200에 `{"code":0,"msg":"정상"}`만 오고 `data`가 없다 |
| HTTP 200인데 `data` 칸이 없으면 **0건이 아니라 실패** (SYNC-1-E4) | 0건으로 믿으면 나중에 삭제 판정이 붙었을 때 혜택 10,942건을 전부 "삭제됨"으로 바꿀 수 있다 |
| 중간 페이지가 실패해도 마지막 페이지까지 계속 부른다. 1페이지가 실패하면 멈춘다 | 1페이지가 없으면 전체 건수(totalCount)를 몰라 몇 페이지까지 부를지 알 수 없다 |
| 검사 실패 10% 이하면 성공 + 실패 건수 기록. 10% 초과면 `SCHEMA_CHANGED`로 중단하고 **아무것도 저장 안 함** | "부분 성공"으로 두면 고장 난 1건이 삭제 판정을 영원히 막는다. 10%를 넘으면 응답 형식이 바뀐 것으로 보고 나머지도 믿지 않는다 |
| 날짜는 `yyyyMMddHHmmss`를 한국 시간으로 **엄격하게** 해석 | 기본(SMART) 해석은 2월 31일을 2월 28일로 조용히 바꾼다 |
| 같은 서비스ID가 두 번 오면 처음 것만 | 결과가 항상 같고 단순하다 |
| 진행 건수는 페이지마다 따로 커밋 | 실행 중에 다른 화면에서 "지금 몇 건째인지" 볼 수 있어야 한다 |
| 시각은 주입한 시계(Clock)로 기록, 테스트 JVM은 UTC | 테스트가 PC 시간대·컨테이너 시계에 흔들리지 않게 |

## 테스트가 잡는 버그 (예시)

| 이렇게 잘못 만들면 | 실패하는 테스트 |
|---|---|
| `data` 칸 없는 응답을 0건으로 처리 | SYNC-1-E4 (단위·통합) |
| 중간 페이지 실패 후 멈춤 | SYNC-1-E3 (호출한 페이지가 정확히 1, 2, 3인지 확인) |
| 빈 값 처리하다 선정기준을 항상 null로 | SYNC-5-E3 "값 있음 → 그대로" 경우 |
| `지원대상`을 `서비스목적` 칸에 넣음 | SYNC-5-N1 (22개 칸 전체 비교) |
| 시간대를 PC 기본값으로 해석 | SYNC-5-E4 (테스트 JVM이 UTC라서 걸림) |
| 서비스 키를 `/`, `=`까지 인코딩하지 않음 | SYNC-1-N1 (가짜 서버가 `ab%2Bc%2Fd%3D%3D` 확인) |
| 상한을 `2000 미만`으로 너무 엄격하게 | SYNC-1-B4 "2,000 허용" |

## 리뷰에서 배운 것

### 1. "구현 안 됨" 예외로 실패하는 것만으로는 Red 증명이 안 된다

- **문제:** 처음 41개 중 35개가 껍데기의 `UnsupportedOperationException`으로 실패했다. 이건 "테스트가 그 코드까지 도달한다"는 것만 보여 준다.
- **확인 방법:** 껍데기가 예외 대신 **가장 단순한 값**(빈 목록, 모든 칸 null, 상태 FAILED)을 돌려주게 잠깐 바꿔 돌렸다. 그때도 단언에서 실패해야 진짜 버그를 잡는 테스트다.
- **결과:** 2개를 빼고 모두 단언에서 실패했다. 남은 2개는 "통과가 정상인 짝 테스트"였다.

### 2. 구조와 맞지 않는 테스트는 구현자에게 테스트를 약하게 만들 핑계를 준다

- **문제:** "실행 중에 진행 건수 조회"(SYNC-9-E1) 테스트는 중간 진행을 봐야 하는데, 수집기는 다 모은 뒤에야 결과를 돌려주는 모양이었다.
- **고친 방법:** 수집기가 페이지마다 알리게(`collect(perPage, PageListener)`) 껍데기 모양을 먼저 바꿨다. 테스트와 구조를 구현 **전에** 맞췄다.

### 3. 흔들리는 테스트의 원인 셋

| 원인 | 고친 방법 |
|---|---|
| `Instant.now()` ± 1ms 비교 (Windows Docker 컨테이너 시계가 어긋날 수 있음) | 고정 시계를 주입하고 정확히 같은지 비교 |
| 개발 PC가 한국 시간이라 시간대 버그가 로컬에서 안 보임 | 테스트 JVM을 UTC로 고정 |
| 백그라운드 실행이 다음 테스트까지 남아 DB를 오염 | 테스트가 끝날 때 백그라운드 실행이 끝나길 기다림 |

### 4. 기존 테스트가 깨지면 Red가 아니라 회귀다

- DB 부품을 추가하자 "앱 켜짐"(`contextLoads`) 테스트가 깨졌다. 구현을 해도 계속 실패하니 Red가 아니다.
- 테스트용 DB만 붙이고 검증 내용은 그대로 둔 채, **사람 승인 후 별도 커밋**으로 고쳤다.
